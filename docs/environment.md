# Environment variables

All values are **public** (publishable) — this project uses no secret keys, and
none should ever be added to a `VITE_*` variable, because everything prefixed
`VITE_` is inlined into the browser bundle at build time.

Copy `.env.example` to `.env` for local development, and set the same three
variables in the build environment of the static host.

| Variable | Controls |
| -------- | -------- |
| `VITE_SUPABASE_URL` | Base URL of the hosted database/API the board reads and writes (e.g. `https://<project-ref>.supabase.co`). |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | Public publishable API key sent with every request. Safe in the bundle; all access is still enforced by row-level security policies. Never put a service-role or secret key here. |
| `VITE_SUPABASE_PROJECT_ID` | Project reference id. Informational, used by generated client tooling. |

The repository's own `.env` additionally carries the non-prefixed twins
(`SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_PROJECT_ID`). They exist for
server-side helpers generated by the platform; the static build does not need
them. That file is generated and should not be hand-edited or committed with real
values.

Notes:

- Values are read at **build** time. After changing one, rebuild — restarting the
  server is not enough.
- No analytics, error-reporting or third-party API keys are used anywhere in the
  app.
- If the database project is ever replaced, update all three variables together;
  a mismatched URL and key fails with an authentication error on the first board
  request.
